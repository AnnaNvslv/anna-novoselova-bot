### 2026-07-24 — Фикс: "Ошибка записи" на booking.html при свободном слоте
После вчерашнего RLS-хардненинга (2026-07-23) онлайн-запись стала падать с алертом `errBook` ("Ошибка записи. Напишите нам: @AnnaNvslv") даже когда слот точно был свободен.

- **Причина**: у анонимной роли на `patients` и `appointments` теперь только `INSERT`-политика, без `SELECT`. Код `submitBooking()` делал `.insert({...}).select().single()` — PostgREST после insert пытается вернуть вставленную строку через `SELECT`, на которую у анонима нет прав; в ответ приходило 0 строк, и `.single()` бросал ошибку. Реальная вставка пациента при этом либо не происходила, либо (для appointments) происходила, но без возврата данных — в обоих случаях пользователь видел `errBook`, при этом сам слот оставался свободен (сбой был раньше апдейта `available_slots`).
- **Фикс (`js/booking.js`)**: id для `patients` и `appointments` теперь генерируются на клиенте (`crypto.randomUUID()`), `.select().single()` убран из обоих insert-ов — читать вставленную строку обратно больше не требуется, достаточно проверить `error`. Это чинит запись без расширения анонимного доступа на чтение (RLS-политики не трогали).
- `booking.html` → `js/booking.js?v=5`.

Этот фикс раскрыл ещё три независимых бага, тоже последствия вчерашней security-миграции (RLS/Auth) — тесты онлайн-записи их не задевали раньше, а с реальным анонимным трафиком все три всплыли по очереди:

- **RPC без прав**: `get_next_appointment_number(date_str text)` осталась без `GRANT EXECUTE` для роли `anon` после миграции 2026-07-23 (RLS настраивали, а грант на саму функцию не выдали). Выдано: `GRANT EXECUTE ON FUNCTION get_next_appointment_number(date_str text) TO anon;`
- **Гонка в генераторе `patient_code`**: `generate_patient_code()` считал следующий код через `SELECT MAX(...)+1 FROM patients` — неатомарно, при почти одновременных вставках два инсерта могли посчитать один и тот же номер и упасть на `patients_patient_code_key`. Переделано на атомарный счётчик: новая таблица `patient_code_counters` (`yy` PK, `seq`, RLS включён без policy — доступна только на уровне БД), инициализирована текущими максимумами по годам; функция переписана на `INSERT ... ON CONFLICT (yy) DO UPDATE SET seq = seq + 1 RETURNING seq` с `SECURITY DEFINER` (чтобы RLS на `patient_code_counters` не мешал триггеру, выполняющемуся от анонимной роли при онлайн-записи).
- **Опечатка при правке функции**: в первой версии переписанной `generate_patient_code()` локальная переменная называлась `yy` — так же, как колонка `yy` в `patient_code_counters`, Postgres не мог разрешить неоднозначность (`column reference "yy" is ambiguous`). Переменную переименовали в `v_yy`.

Проверено на живом сайте — онлайн-запись проходит.

**Подключён Supabase MCP-коннектор** (проект `ncfqiznpilikwmpqhapb`) для будущих сессий — в перспективе Claude сможет сам выполнять SQL-диагностику и миграции вместо пошагового копирования в SQL Editor.
